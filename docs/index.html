Sextant · Plan · Version 1 (v0.1.0)

Sextant Version 1

A command-line tool that turns an Android APK into clean, structured data that people and AI agents can read. Version 1 does one small job end to end: it reads the APK's identity, manifest, permissions and components and writes them out as stable JSON and JSONL.

01Goal

Ship a small, solid CLI that works end to end: APK in, structured app facts out. Someone should be able to install it, run one command and get correct output.

Development rule: each version adds a limited set of features but is fully finished: built, tested, documented and released. Version 2 starts only after Version 1 is released.

Why start with the manifest: it is the smallest part of an APK that is still useful. It shows what the app is, what it asks for and how other apps can reach it. It also forces us to build the whole pipeline (CLI, parsing, model, writers, tests, release) that every later version reuses.

02Scope

IN Version 1

  • Input: one .apk file
  • App identity: package, version, SDK levels, hashes, size
  • Signing: schemes (v1–v4) and certificate fingerprints
  • Full decoded manifest as structured JSON
  • Permissions: requested and declared, with a dangerous flag
  • Components: activities, aliases, services, receivers, providers
  • Whether each component is exported, including Android's default rules
  • Intent filters, deep links, launcher activity
  • Basic APK layout: DEX count and native ABIs
  • summary.md written for AI agents
  • Commands: extract, info, --version, --help

OUT Later versions

  • Classes, methods, fields, calls → V2
  • SQLite index, sql, find → V3
  • Callers/callees, Java source view → V4
  • Resources, strings, SDK detection, endpoints → V5
  • Native binary, MCP server → V6
  • .xapk / .apks / .aab split bundles
  • Data-flow analysis, AI "ask" commands
  • Version diffs, GUI of any kind

03CLI design

Commands

sextant extract <app.apk> [-o <dir>] [--force] [--quiet]
sextant info    <dir | app.apk> [--json]
sextant --version
sextant --help
Command / flagBehaviour
extractParses the APK and writes the output folder. The default output path is ./<apk-name>.sextant/.
-o, --outOutput directory.
--forceOverwrites a non-empty output directory. Without it, Sextant refuses so it never deletes data by accident.
--quietNo progress output; errors still go to stderr.
infoPrints a short human-readable summary. Accepts an extracted folder, or an APK directly (parsed in memory, nothing written).
--jsonPrints machine-readable JSON to stdout. Used by scripts and AI agents.

Exit codes

CodeMeaning
0Success
1Usage error (bad flags, missing argument)
2Input error (file missing, not a zip, no AndroidManifest.xml)
3Output error (directory not empty without --force, not writable)
4Unexpected internal error (bug; prints a short message and a hint to report it)

04Output folder

signal/
  summary.md          ← agents read this first (< 60 lines)
  meta.json           ← one object: identity, signing, layout
  manifest.json       ← full decoded manifest tree
  permissions.jsonl   ← one permission per line
  components.jsonl    ← one component per line
RuleReason
A single object goes in .json; a list of records goes in .jsonlJSONL can be streamed, searched with grep and jq, and counted with wc -l. It scales to the millions of records V2 will produce.
Every JSONL line is self-containedFull names on every line and no numeric IDs to join. An agent can grep one line and understand it.
summary.md at the rootOne short read gives an agent the overview and tells it which file holds what.
snake_case keys, fixed key orderPredictable for scripts and stable in diffs.

05Schemas

Every file carries schema_version (in meta.json). The schema version is 1 for this release. It changes only when the output format changes, separately from the tool's version.

meta.json

{
  "schema_version": 1,
  "tool": { "name": "sextant", "version": "0.1.0" },
  "file": { "name": "signal.apk", "size_bytes": 191260442, "sha256": "9f2c…a71e" },
  "package": "org.thoughtcrime.securesms",
  "version_name": "7.20.4",
  "version_code": 1482,
  "min_sdk": 21,
  "target_sdk": 34,
  "compile_sdk": 34,
  "label": "Signal",
  "application_class": "org.thoughtcrime.securesms.ApplicationContext",
  "flags": {
    "debuggable": false,
    "allow_backup": false,
    "uses_cleartext_traffic": null,
    "network_security_config": "@xml/network_security_config",
    "extract_native_libs": false
  },
  "signing": {
    "schemes": ["v2", "v3"],
    "certificates": [
      { "sha256": "29:F3:…:8A", "sha1": "…", "subject": "CN=Whisper Systems, …", "issuer": "…",
        "not_before": "2011-…", "not_after": "2039-…" }
    ]
  },
  "layout": { "dex_files": 6, "native_abis": ["arm64-v8a", "armeabi-v7a", "x86", "x86_64"] }
}

null means the attribute is absent from the manifest. We never guess a value. Resource references (@xml/…, @string/…) are resolved when possible; otherwise the raw reference is kept.

permissions.jsonl

{"name":"android.permission.CAMERA","kind":"uses-permission","max_sdk":null,"dangerous":true,"protection_level":null,"custom":false}
{"name":"android.permission.INTERNET","kind":"uses-permission","max_sdk":null,"dangerous":false,"protection_level":null,"custom":false}
{"name":"org.thoughtcrime.securesms.ACCESS_SECRETS","kind":"declared","max_sdk":null,"dangerous":false,"protection_level":"signature","custom":true}

kind is one of uses-permission, uses-permission-sdk-23 or declared (from <permission>). dangerous comes from a bundled list of Android's dangerous platform permissions.

components.jsonl

{"type":"activity","name":"org.example.RoutingActivity","exported":true,"exported_source":"explicit","enabled":true,"permission":null,"process":null,"launcher":true,"target_activity":null,"authorities":[],"intent_filters":[{"actions":["android.intent.action.MAIN"],"categories":["android.intent.category.LAUNCHER"],"data":[],"priority":0,"auto_verify":false}]}
{"type":"activity","name":"org.example.DeepLinkActivity","exported":true,"exported_source":"default","enabled":true,"permission":null,"process":null,"launcher":false,"target_activity":null,"authorities":[],"intent_filters":[{"actions":["android.intent.action.VIEW"],"categories":["android.intent.category.BROWSABLE","android.intent.category.DEFAULT"],"data":[{"scheme":"https","host":"example.org","port":null,"path":null,"path_prefix":"/join","path_pattern":null,"mime_type":null}],"priority":0,"auto_verify":true}]}
{"type":"provider","name":"org.example.PartProvider","exported":false,"exported_source":"explicit","enabled":true,"permission":null,"process":null,"launcher":false,"target_activity":null,"authorities":["org.example.part"],"intent_filters":[]}
FieldRule
typeactivity, activity-alias, service, receiver or provider
nameAlways fully qualified. Relative names like .Main are expanded with the package.
exportedThe effective value. If the attribute is missing, Android's default applies: true when the component has an intent filter; for providers, true only when targetSdk ≤ 16.
exported_sourceexplicit (written in the manifest) or default (worked out by the rule above). This keeps the result honest.
launcherHas the MAIN + LAUNCHER intent filter.

06Engineering rules

RuleWhat it means in practice
DeterministicThe same APK always gives byte-identical output: records sorted by (type, name), fixed key order, no timestamps or absolute paths, \n line endings, UTF-8.
TruthfulAbsent values are null, not guessed. Derived values say they are derived (exported_source).
Fault tolerantMalformed or obfuscated manifests (a common anti-analysis trick) must not crash the tool. Skip the broken piece, record a warning in meta.json → warnings[], and continue.
FastVersion 1 reads only the manifest, signing block and zip index. It never decompiles code. Target: under 3s for a 200 MB APK.
SafeNever executes anything from the APK. Guards against zip bombs and path traversal in entry names. Never writes outside --out.
Clean streamsData goes to stdout; progress and errors go to stderr. --json output contains nothing else, so it can be piped safely.
Core / CLI splitAll logic lives in the core module, which has no CLI code. The CLI is a thin layer, so core can later become a library and an MCP server.

09Tasks, in order

  1. Day 1
    Project skeleton
    Gradle multi-module (core, cli), version catalog, ktlint and detekt, an empty sextant --version working through the fat jar and launcher script. CI green on all three operating systems.
  2. Day 1–2
    Decoder spike
    Confirm jadx-core can decode the manifest and resources.arsc without loading DEX code, and measure the time on a 200 MB APK. If it can't, switch to apktool-lib. Record the decision in the README.
  3. Day 2
    ApkReader
    Open the zip safely, compute sha256 and size, count DEX files, list native ABIs, and reject non-zip or manifest-less files with exit code 2.
  4. Day 3–4
    Manifest decoding + mapping
    Binary XML → tree → manifest.json. Map it to the meta fields, permissions and components. Expand relative names and resolve resource references.
  5. Day 5
    Exported rules + intent filters
    Effective exported value with exported_source, launcher detection, deep-link data, activity aliases and provider authorities. Unit-test every rule branch.
  6. Day 6
    Signing
    Use apksig to get the schemes and certificate fingerprints. An unsigned APK is valid and gives an empty list.
  7. Day 7
    Deterministic writers + summary.md
    JSON and JSONL writers with fixed order, plus summary.md. Running extract twice must produce identical output.
  8. Day 8
    CLI commands
    extract with -o, --force and --quiet; info on a folder or an APK, with --json. Exit codes, plus clear error messages that suggest a fix.
  9. Day 9–10
    Fixtures, golden tests, real-APK sweep
    Build the fixture APKs, write the golden files, and run the external sweep. Fix every crash and wrong value it finds.
  10. Day 11
    Docs
    README: a 30-second demo GIF, install, usage, output format reference, the AI-agent section and limitations. CHANGELOG entry.
  11. Day 12
    Release v0.1.0
    Tag, run JReleaser, publish the GitHub Release and Homebrew tap formula, then install from scratch on a clean machine to verify.

10Testing strategy

1 · Unit tests (core)

Every mapper and rule is tested on its own: relative-name expansion, each branch of the export defaults (with and without intent filters, providers above and below targetSdk 17), the dangerous-permission lookup, null handling and certificate formatting.

2 · Downloaded real-APK corpus

All test APKs are real apps, downloaded from F-Droid and official project sites. We never build our own. Each one is pinned by URL and sha256 in fixtures/external.lock and downloaded by scripts/fetch-apks.sh into the gitignored fixtures/external/.

Each Android behaviour rule (exported defaults, aliases and so on) is unit-tested with small hand-written inputs to the mapper. Those are Kotlin test data, not built APKs.

3 · Golden-file tests

For each corpus APK, the full output folder is compared byte for byte with fixtures/golden/<app>/, which is committed. The APKs themselves are not. Running ./gradlew updateGolden regenerates the golden files, and the diff is reviewed. Any change to the output format shows up in review.

4 · Determinism test

Extract the same APK twice, into different paths and at different times, and require identical files. This runs in CI on all three operating systems, which catches line-ending and locale bugs.

5 · Real-world sweep

Run the full corpus on every change. Pass criteria: no crashes, no warnings we don't understand, and spot checks against aapt2 dump badging and apkanalyzer manifest print. New APK types are added to the corpus whenever a bug is found.

6 · Bad-input tests

An empty file, a text file renamed .apk, a zip without a manifest, a truncated APK, a manifest with junk chunks, an entry name with ../, a zip bomb, a non-empty output directory and a read-only output directory. Each must give the right exit code and a clear message, never a stack trace.

7 · CLI end-to-end tests

Run the real fat jar as a subprocess and assert stdout, stderr and exit codes for every command and flag. Check that --json output parses as JSON and contains nothing else.

8 · Performance check

Time extract on the largest external APK in CI and fail if it takes over 3 seconds. Report peak memory.

11Release and distribution

Sextant is a CLI tool, so people install it as an app, not as a dependency. Maven Central is not the right channel for the CLI. It becomes relevant later, for publishing sextant-core as a library once its API is stable (around V3).

ChannelWhenUser experience
GitHub ReleasesV1Download sextant-0.1.0.zip (jar + bin/sextant + bin/sextant.bat) with a sha256 checksum file. Unzip and add to PATH.
Homebrew tapV1brew install rajumark/tap/sextant. The formula depends on openjdk, so Java is installed automatically.
SDKMAN / ScoopV2–V3JVM-native and Windows installers, generated by the same JReleaser config.
Native binaries (GraalVM)V6Java no longer needed; instant startup. Homebrew switches to native bottles.
Maven Central (io.github.rajumark:sextant-core)V3+For developers embedding the engine in their own tools.

#   → GitHub Release (zip + checksums + changelog notes)

Versioning follows semver, with 0.x while the output schema is still evolving. Version 1 of this plan = v0.1.0; Version 2 = v0.2.0, and so on. 1.0.0 marks a stable schema promise.

12Risks

RiskMitigation
jadx-core's resource decoder can't be used without loading the code, making it slow or heavyDay-1 spike measures this. Fallback: apktool-lib, or a small self-written binary-XML parser (the format is small and well documented).
Obfuscated or deliberately malformed manifestsA tolerant decoder, a warnings list, and sweep fixtures that include hostile cases.
Resource references that can't be resolvedKeep the raw @type/name string; never drop the value.
The schema needs to change after people adopt itschema_version from day one; documented changes in the CHANGELOG.
Scope creep into V2 featuresThis page is the contract: anything not in "IN" waits.

Usage note for the README: analyze only apps you own, apps with open-source licenses, or apps you have permission to examine.
