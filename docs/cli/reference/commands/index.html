    Commands¶

    Every command prints help with -h / --help. Commands that read an extraction take the output folder; info and icon also accept an APK directly. Progress and errors go to stderr, results to stdout.

    Usage: sextant [<options>] <command> [<args>]...

  Turn an Android APK into structured data for people and AI agents.

Options:
  -V, --version  Show the version and exit
  -h, --help     Show this message and exit

Commands:
  extract     Extract structured data from an APK into a folder.
  info        Show a short summary of an APK or an extracted folder.
  sql         Run read-only SQL over index.sqlite. Use --schema to see the tables.
  find        Find anything containing the text: classes, methods, fields, strings, components, permissions, deep links, resources, endpoints, SDKs, libraries and native symbols.
  class       Show a class: hierarchy, fields, methods, who calls it and the strings it uses.
  callers     Show who calls a method, as a tree. Calls through an interface or superclass are recorded against that base method.
  callees     Show what a method calls, as a tree. External (framework/library) methods are leaves.
  source      Print decompiled Java (jadx) for one class or method. Names are kept as in the bytecode, matching the index, unless --mapping gives the originals.
  grep        Search decompiled Java for text: every matching line with its class, method and line number. Finds what `find` can't (code bodies, field use, API calls). The first search decompiles the app and keeps the code in a local cache, so later searches are quick; --package narrows a first search on big apps.
  insights    Show what the app is built with: frameworks, SDKs, libraries, endpoints and native code.
  endpoints   List URLs found in code strings, resources, deep links and manifest values, with their sources.
  mcp         Run an MCP server on stdin/stdout so AI agents can extract, search and query APKs. Tools: extract, summary, find, class, callers, callees, sql, source, insights, xref, reach, smali, icon, findings, endpoints.
  diff        Compare two extracted versions: app facts, permissions, components, deep links, SDKs, libraries, hosts, URLs, native code, packages, classes, strings and resources.
  findings    Show review findings (debuggable, cleartext, exported components, WebView bridges, weak crypto, trust-all TLS, embedded secrets, …) with evidence. They are static observations to check, not proven vulnerabilities.
  xref        Where is a class or field used: instantiations, casts, instanceof, const-class, calls into its methods, field reads and writes.
  reach       Find call paths from an entry point (e.g. an exported activity) to target methods, following virtual and interface dispatch into subclasses. Static approximation: reflection, framework callbacks and native code are not followed.
  smali       Print smali (bytecode assembly) for one class or method. Works where decompiling fails; # 0x… offsets match the code files.
  icon        Find the app icon: every file behind android:icon (or --round) per density, adaptive icon layers, pixel sizes, and the best file to use. -o saves it.
  components  List activities, aliases, services, receivers and providers with verdicts: launcher, app-link, deep-link, hidden-entry, task-hijack, lock-screen, exported-by-default, guarded, disabled.
  component   Explain one component: verdicts with reasons, activity attributes, intent filters in plain words, deep links, aliases and ready-to-run adb commands.
  app         Show the Application class and the startup order: AppComponentFactory, attachBaseContext, content providers (androidx.startup initializers), onCreate; with an extracted folder, also their calls and the SDKs they start.
  res         List strings (every locale, plurals, arrays), resource ids, styles and themes, drawables, layouts, menus, navigation graphs, assets and XML configs. References are shown as written and resolved; NAME shows one entry and who uses it.
  sdks        Show SDKs and libraries by role (analytics, ads, crash reporting, auth, database, UI, …) with versions when an artifact proves them. With several apps, show which SDKs appear where and filter apps by SDK, category or version.
  deobf       Look up names in a ProGuard/R8 mapping.txt, both ways: original -> obfuscated for classes, fields and methods. Pass the same file as --mapping to `source` and `grep` to read the code with original names.

    extract¶

    Usage: sextant extract [<options>] <apk>

  Extract structured data from an APK into a folder.

Options:
  -o, --out=<path>  Output directory (default: ./<apk-name>.sextant/)
  --force           Overwrite Sextant's files in a non-empty output directory
  -q, --quiet       No progress output
  --no-index        Skip index.sqlite (no sql/find/class)
  --no-code         Skip code structure (classes, methods, calls); manifest-level files only
  -h, --help        Show this message and exit

Arguments:
  <apk>  APK file to analyze

    info¶

    Usage: sextant info [<options>] <target>

  Show a short summary of an APK or an extracted folder.

Options:
  --json      Machine-readable JSON on stdout
  -h, --help  Show this message and exit

Arguments:
  <target>  An extracted folder, or an APK (analyzed in memory, nothing written)

    sql¶

    Usage: sextant sql [<options>] <dir> [<query>]

  Run read-only SQL over index.sqlite. Use --schema to see the tables.

Options:
  --json, --csv  Output format
  --schema       Print the tables and views instead of running a query
  --limit=<int>  Maximum rows to print (default 1000, 0 = no limit)
  -h, --help     Show this message and exit

Arguments:
  <dir>    An extracted folder (or its index.sqlite)
  <query>  SQL to run (read-only)

    find¶

    Usage: sextant find [<options>] <dir> <text>

  Find anything containing the text: classes, methods, fields, strings, components, permissions, deep links, resources, endpoints, SDKs, libraries and native symbols.

Options:
  --kind=(class|method|field|string|component|permission|deep_link|resource|endpoint|sdk|library|native_symbol|finding|string_resource)  Only this kind
  --limit=<int>                                                                                                                          Maximum results (default 50)
  --json                                                                                                                                 One JSON object per line
  -h, --help                                                                                                                             Show this message and exit

Arguments:
  <dir>   An extracted folder
  <text>  Text to find (any part of a name or string)

    class¶

    Usage: sextant class [<options>] <dir> <name>

  Show a class: hierarchy, fields, methods, who calls it and the strings it uses.

Options:
  --json      Machine-readable JSON
  -h, --help  Show this message and exit

Arguments:
  <dir>   An extracted folder
  <name>  Class name: com.app.Login, Lcom/app/Login; or just Login

    callers¶

    Usage: sextant callers [<options>] <dir> <method>

  Show who calls a method, as a tree. Calls through an interface or superclass are recorded against that base method.

Options:
  -d, --depth=<int>  How many levels to follow (default 3)
  --fan-out=<int>    Maximum children per method (default 15)
  --json             The tree as JSON (one array of root trees)
  -h, --help         Show this message and exit

Arguments:
  <dir>     An extracted folder
  <method>  Method: Lcom/a/B;->m(I)V, Lcom/a/B;->m, com.a.B.m, B.m or just m

    callees¶

    Usage: sextant callees [<options>] <dir> <method>

  Show what a method calls, as a tree. External (framework/library) methods are leaves.

Options:
  -d, --depth=<int>  How many levels to follow (default 3)
  --fan-out=<int>    Maximum children per method (default 15)
  --json             The tree as JSON (one array of root trees)
  -h, --help         Show this message and exit

Arguments:
  <dir>     An extracted folder
  <method>  Method: Lcom/a/B;->m(I)V, Lcom/a/B;->m, com.a.B.m, B.m or just m

    source¶

    Usage: sextant source [<options>] <apk> <target>

  Print decompiled Java (jadx) for one class or method. Names are kept as in the bytecode, matching the index, unless --mapping gives the originals.

Options:
  --mapping=<path>  ProGuard/R8 mapping.txt: show original class, method and field names; TARGET may then use the original name
  -h, --help        Show this message and exit

Arguments:
  <apk>     The APK (decompiling needs the bytecode)
  <target>  Class (com.a.B, Lcom/a/B;) or method (Lcom/a/B;->m(I)V, Lcom/a/B;->m, com.a.B.m)

    grep¶

    Usage: sextant grep [<options>] <apk> <text>

  Search decompiled Java for text: every matching line with its class, method and line number. Finds what `find` can't (code bodies, field use, API calls). The first search decompiles the app and keeps the code in a local cache, so later searches are quick; --package narrows a first search on big apps.

Options:
  --regex           Treat TEXT as a regular expression
  --case            Match case
  --package=<text>  Only classes whose name starts with this, e.g. com.app (much faster on big apps)
  --limit=<int>     Stop after this many matching lines (default 200)
  --mapping=<path>  ProGuard/R8 mapping.txt: search and show original names
  --json            One JSON object per match
  --no-cache        Don't read or write the local cache of decompiled code
  -h, --help        Show this message and exit

Arguments:
  <apk>   The APK or split bundle (searching needs the bytecode)
  <text>  Text to find in the code (case-insensitive), or a regular expression with --regex

    insights¶

    Usage: sextant insights [<options>] <dir>

  Show what the app is built with: frameworks, SDKs, libraries, endpoints and native code.

Options:
  --json      One JSON object
  -h, --help  Show this message and exit

Arguments:
  <dir>  An extracted folder

    endpoints¶

    Usage: sextant endpoints [<options>] <dir>

  List URLs found in code strings, resources, deep links and manifest values, with their sources.

Options:
  --host=<text>  Only URLs whose host contains this text
  --limit=<int>  Maximum URLs (default 200)
  --json         One JSON object per URL
  -h, --help     Show this message and exit

Arguments:
  <dir>  An extracted folder

    mcp¶

    Usage: sextant mcp [<options>]

  Run an MCP server on stdin/stdout so AI agents can extract, search and query APKs. Tools: extract, summary, find, class, callers, callees, sql, source, insights, xref, reach, smali, icon, findings, endpoints.

Options:
  --dir=<path>  Start with this extraction folder as the current app
  --apk=<path>  The APK for `source` (and the default for `extract`)
  -h, --help    Show this message and exit

    diff¶

    Usage: sextant diff [<options>] <old> <new>

  Compare two extracted versions: app facts, permissions, components, deep links, SDKs, libraries, hosts, URLs, native code, packages, classes, strings and resources.

Options:
  --show=<int>  Items to list per section (default 15; totals are always exact)
  --json        The full report as JSON
  -h, --help    Show this message and exit

Arguments:
  <old>  Extraction folder of the older version
  <new>  Extraction folder of the newer version

    findings¶

    Usage: sextant findings [<options>] <dir>

  Show review findings (debuggable, cleartext, exported components, WebView bridges, weak crypto, trust-all TLS, embedded secrets, …) with evidence. They are static observations to check, not proven vulnerabilities.

Options:
  --severity=(info|low|medium|high)  Minimum severity to show
  --json                             One JSON object per finding
  --sarif                            SARIF 2.1.0 for GitHub code scanning and other dashboards
  --fail-on=(info|low|medium|high)   Exit with code 5 if any finding is at or above this severity (for CI); the output is unchanged
  -h, --help                         Show this message and exit

Arguments:
  <dir>  An extracted folder

    xref¶

    Usage: sextant xref [<options>] <dir> <target>

  Where is a class or field used: instantiations, casts, instanceof, const-class, calls into its methods, field reads and writes.

Options:
  --limit=<int>  Maximum rows (default 200)
  --json         One JSON object per row
  -h, --help     Show this message and exit

Arguments:
  <dir>     An extracted folder
  <target>  Class (com.a.B, Lcom/a/B;, B) or field (Lcom/a/B;->f:I, Lcom/a/B;->f, com.a.B.f)

    reach¶

    Usage: sextant reach [<options>] <dir> <from> <to>

  Find call paths from an entry point (e.g. an exported activity) to target methods, following virtual and interface dispatch into subclasses. Static approximation: reflection, framework callbacks and native code are not followed.

Options:
  --depth=<int>  Maximum call depth (default 10)
  --paths=<int>  Maximum paths to report (default 5)
  --json         The result as JSON
  -h, --help     Show this message and exit

Arguments:
  <dir>   An extracted folder
  <from>  Entry point: a component/class (com.a.LoginActivity) or a method
  <to>    Target: Ljavax/crypto/Cipher;->getInstance, Cipher.getInstance, okhttp3/ or a method name

    smali¶

    Usage: sextant smali [<options>] <apk> <target>

  Print smali (bytecode assembly) for one class or method. Works where decompiling fails; # 0x… offsets match the code files.

Options:
  -h, --help  Show this message and exit

Arguments:
  <apk>     The APK
  <target>  Class (com.a.B, Lcom/a/B;) or method (Lcom/a/B;->m(I)V, Lcom/a/B;->m)

    icon¶

    Usage: sextant icon [<options>] <target>

  Find the app icon: every file behind android:icon (or --round) per density, adaptive icon layers, pixel sizes, and the best file to use. -o saves it.

Options:
  --round                                     Use android:roundIcon instead of android:icon
  --layer=(foreground|background|monochrome)  For adaptive icons: pick a layer instead of the full icon
  -o, --out=<path>                            Save the chosen file here (needs the APK)
  --json                                      All icon data as JSON
  -h, --help                                  Show this message and exit

Arguments:
  <target>  An APK (fast: manifest + resources only) or an extracted folder

    components¶

    Usage: sextant components [<options>] <target>

  List activities, aliases, services, receivers and providers with verdicts: launcher, app-link, deep-link, hidden-entry, task-hijack, lock-screen, exported-by-default, guarded, disabled.

Options:
  --type=(activity|activity-alias|service|receiver|provider)                                                                                                                                                        Only this type; repeat for several (activity includes aliases with --type activity-alias)
  --tag=(launcher|app-link|deep-link|hidden-entry|unguarded|sensitive-role|system-role|boot|foreground|task-hijack|lock-screen|uri-grants|file-provider|isolated|direct-boot|exported-by-default|guarded|disabled)  Only components with this verdict; repeat to require several
  --exported                                                                                                                                                                                                        Only exported components
  --search=<text>                                                                                                                                                                                                   Only names, deep links, authorities, permissions or processes containing this text
  --json                                                                                                                                                                                                            One JSON object per component: component, review, attributes
  -h, --help                                                                                                                                                                                                        Show this message and exit

Arguments:
  <target>  An extracted folder, or an APK (analyzed in memory, nothing written)

    component¶

    Usage: sextant component [<options>] <target> <name>

  Explain one component: verdicts with reasons, activity attributes, intent filters in plain words, deep links, aliases and ready-to-run adb commands.

Options:
  --json      One JSON object: component, review, attributes
  -h, --help  Show this message and exit

Arguments:
  <target>  An extracted folder, or an APK (analyzed in memory, nothing written)
  <name>    Class name, or a unique suffix such as .MainActivity

    app¶

    Usage: sextant app [<options>] <target>

  Show the Application class and the startup order: AppComponentFactory, attachBaseContext, content providers (androidx.startup initializers), onCreate; with an extracted folder, also their calls and the SDKs they start.

Options:
  --json      One JSON object
  -h, --help  Show this message and exit

Arguments:
  <target>  An extracted folder (follows startup calls with its index), or an APK (manifest only)

    res¶

    Usage: sextant res [<options>] <target> <kindname> [<name>]

  List strings (every locale, plurals, arrays), resource ids, styles and themes, drawables, layouts, menus, navigation graphs, assets and XML configs. References are shown as written and resolved; NAME shows one entry and who uses it.

Options:
  --search=<text>                                                            Only entries whose name or value contains this text
  --flag=(used|unused|url|email|secret-like|format|html|untranslated|empty)  string-keys only: used, unused, url, email, secret-like, format, html, untranslated, empty
  --config=<text>                                                            Only this configuration, e.g. fr, night, default
  --limit=<int>                                                              Maximum rows (default 500)
  --json                                                                     One JSON object per record
  -h, --help                                                                 Show this message and exit

Arguments:
  <target>    An extracted folder, or an APK (analyzed in memory, nothing written)
  <kindname>  What to list: strings, string-keys, ids, styles, drawables, layouts, menus, navigation, assets, xml, refs
  <name>      Show one entry in full (all configurations) and what references it

    sdks¶

    Usage: sextant sdks [<options>] <targets>...

  Show SDKs and libraries by role (analytics, ads, crash reporting, auth, database, UI, …) with versions when an artifact proves them. With several apps, show which SDKs appear where and filter apps by SDK, category or version.

Options:
  --category=<text>  Only apps that have an SDK in this category; repeat to require several (ads, analytics, …)
  --sdk=<text>       Only apps that contain this SDK or library (name or group:artifact, case-insensitive substring); repeat to require several
  --below=<text>     With one --sdk: only apps whose version of it is lower than this (e.g. 4.9.0)
  --json             One JSON object per app (its SDK profile)
  -h, --help         Show this message and exit

Arguments:
  <targets>  Extracted folders and/or APKs (APKs are analyzed in memory)

    deobf¶

    Usage: sextant deobf [<options>] <mappingfile> <name>

  Look up names in a ProGuard/R8 mapping.txt, both ways: original -> obfuscated for classes, fields and methods. Pass the same file as --mapping to `source` and `grep` to read the code with original names.

Options:
  --limit=<int>  Maximum lines (default 100)
  -h, --help     Show this message and exit

Arguments:
  <mappingfile>  The mapping.txt R8 or ProGuard wrote for this build
  <name>         Any part of an original or obfuscated class name, or a member name
